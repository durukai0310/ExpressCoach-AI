# ExpressCoach · 已知局限清单 (Known Limitations)

> **Day 32 边界测试产物** | 2026-07-02 | 成员A
>
> 本文档记录系统在当前阶段的已知局限，按影响程度从高到低排列。
> 评审时可主动提及这些局限 + 后续优化方案，展现工程诚实性。

---

## 🔴 高影响 (影响核心功能正确性)

### 1. 空输入进入交互模式而非报错
- **现象**: `node src/index.js ""` 时进入交互模式，而不是提示"请输入场景描述"后退出
- **根因**: CLI参数为空字符串时 `scenario.trim()` 为空，代码直接跳转到 `interactiveMode()`
- **影响**: 非预期行为，用户可能困惑
- **修复方向**: 增加空输入检测，CLI模式下输出提示后 `process.exit(0)`

### 2. 纯Emoji输入意图识别置信度极低
- **现象**: `"😅😅😅"` → 置信度仅35%，主意图被误判为"反馈"
- **根因**: 意图识别模型未针对emoji语义做训练，关键词匹配无法覆盖emoji
- **影响**: 用户使用emoji表达情绪时无法得到准确分析
- **修复方向**: 添加emoji→文字映射词典作为预处理层（如 😅→尴尬/为难）

### 3. 并行化意图识别+关系判断引入竞态风险
- **现象**: Day 32步骤2尝试 `Promise.all([recognizeIntent, hybridAnalyze])` 并行化
- **根因**: 两个模块共用同一个 API Key 和网络连接池，高并发时可能触发 API 限流
- **影响**: 并行执行时偶发 429 错误，导致其中一个步骤失败
- **修复方向**: 实现请求队列 + 指数退避重试；或保持串行但优化单次API超时

## 🟡 中影响 (影响体验或边缘场景)

### 4. 纯英文输入缺乏跨语言适配
- **现象**: 英文 `"I want to reject..."` 能识别但中文关键词匹配层完全失效
- **根因**: 规则层关键词词典仅覆盖中文，LLM虽能理解英文但无规则兜底
- **影响**: 国际化场景下准确率下降约15-20%
- **修复方向**: 添加英文关键词词典，或将规则层改为语义embedding匹配

### 5. 全链路耗时 ~15s 未达 <5s 目标
- **现象**: 串行执行三步(意图→关系→三版本)时总耗时约10-15s
- **根因**: 三个步骤各自调用API，每个API调用1-3s，串行累加 + 网络抖动
- **影响**: 用户体验不够流畅，Demo演示时等待明显
- **修复方向**: 意图+关系并行（节省~2s），三版本内部已并行；考虑流式输出

### 6. 关系判断规则层与LLM层频繁不一致
- **现象**: 边界测试中5/6的场景规则层与LLM层判断不一致（如"拒绝爸爸"→规则判"父母"/LLM判"家人"）
- **根因**: 规则词典粒度粗（仅按关键词匹配），LLM理解更细但受prompt影响大
- **影响**: 混合模式以LLM为准时规则层形同虚设；实际规则贡献度 < 0.3
- **修复方向**: 细化规则词典（如区分"爸爸/妈妈/父母"层级），或上调LLM权重至0.8

### 7. 双重关系检测存在误触发
- **现象**: "向同事求助借钱"场景同时触发"同事(关系好)"和"同事(一般)"双重检测
- **根因**: 同事关键词在两个子类中均有匹配，双信号触发机制过于敏感
- **影响**: 非真正双重关系场景被标记为双重关系，敏感度被不必要地+0.2
- **修复方向**: 增加双信号阈值（如要求两个不同大类的关键词才算双重关系）

## 🟢 低影响 (边界或极端情况)

### 8. 超长输入 (>500字) 未做截断处理
- **现象**: 输入超过模型的context窗口限制时，API调用失败
- **根因**: 未对输入长度做检查和截断
- **影响**: 极端长输入场景下系统直接报错
- **修复方向**: 添加输入长度检查，超过500字时自动摘要或截断提醒

### 9. 特殊字符/脚本注入未过滤
- **现象**: 用户输入包含 `\n`、`\r`、Markdown标记等特殊字符时可能干扰SOUL prompt解析
- **根因**: 输入直接拼接进prompt，未做sanitize处理
- **影响**: 恶意构造的输入可破坏prompt结构（prompt injection风险）
- **修复方向**: 对用户输入做转义处理，或使用结构化的prompt模板

### 10. 并发多用户场景下 SQLite 写锁竞争
- **现象**: 高并发时 `SQLITE_BUSY` 错误
- **根因**: SQLite 不支持高并发写入，WAL模式仅缓解不根治
- **影响**: 多用户同时使用时案例保存可能失败（当前静默忽略）
- **修复方向**: 切换到 PostgreSQL/MySQL，或加入写队列 + 重试机制

### 11. M5反应预测模块在非高情商版本上准确率下降
- **现象**: 当用户选择温和版或坚定版时，M5预测对方反应的准确率低于高情商版
- **根因**: M5模块的soul prompt设计时参考了高情商版的风格，对其他版本适配不足
- **影响**: 温和版/坚定版的反应预测可信度降低
- **修复方向**: 为每个版本设计独立的预测prompt

### 12. 训练数据存在类不平衡
- **现象**: 拒绝类场景占训练数据的~40%，求助类仅~10%
- **根因**: 初始数据采集偏向高频场景
- **影响**: 低频意图（求助/反馈）的识别准确率可能低于报告值
- **修复方向**: 数据增强 + 过采样低频类别
