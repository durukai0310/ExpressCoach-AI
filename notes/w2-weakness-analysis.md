## 弱点分析

### 弱点1: 全流程耗时超标 ⚠️ (严重度: 中)

**现象**: 平均 7.3s，远超 5s 目标。最慢场景 (8.0s) 几乎是最快场景 (6.7s) 的 1.2 倍。

**根因分析**:
- 三次串行 API 调用 (意图 → 关系 → 三版本) 每次约 1-2s 网络延迟
- 三版本虽然是 Promise.all 并行，但 3 个 API 调用都在等待最慢者
- 无请求缓存/预加载机制

**对策**:
- [ ] 短期: 意图识别和关系判断可并行执行 (不依赖彼此结果)
- [ ] 中期: 高频场景结果缓存 (相同场景 5min 内直接返回)
- [ ] 长期: 小模型本地部署做意图识别 (无需 API 调用)

### 弱点2: 规则与LLM关系判断一致性偏低 ⚠️ (严重度: 低)

**现象**: 10 个场景中，规则匹配与 LLM 精调在 6 个场景中不一致 (40% 一致率)。

| 场景 | 规则判断 | LLM修正 | 分析 |
|------|---------|---------|------|
| 拒老板加班 | 上级 | 上下级 | 语义一致，命名差异 |
| 领导安排不合理 | 上级 | 上下级 | 同上 |
| 向老板请假 | 上级 | 上下级 | 同上 |
| 同事让我帮忙 | 同事(一般) | 同事 | 子类型差异 |
| 妈妈催结婚 | 父母 | 家人 | LLM更泛化 |
| 陌生人借钱 | 陌生人(疏远/不明/纯情感) | 陌生人(疏远/平等/弱利益) | LLM修正权力+利益 |

**根因分析**:
- 规则词典命名 (如"上级""同事(一般)") 与 LLM 输出命名 ("上下级""同事") 不统一
- "上级"vs"上下级" 语义相同但字符串不同 → 误判为"不一致"
- LLM 在利益关联判断上更准确 (理解"借钱"蕴含利益关系)

**对策**:
- [x] 规则词典是参考而非决策，LLM 修正本就是设计意图
- [ ] 统一规则词典与 LLM 输出的关系类型命名
- [ ] 不一致时增加解释性输出 (说明为什么 LLM 修正了规则)

### 弱点3: 最易混淆的意图边界 ⚠️ (严重度: 低)

**分析**: 测试中意图分类 100% 准确，但以下边界在理论上易混淆:

| 混淆对 | 区分关键 | 边界测试 |
|--------|---------|---------|
| 拒绝 vs 设边界 | 拒绝=对具体请求说"不"，设边界=对行为模式划定界限 | "同事让我帮忙"→正确归拒绝 ✅ |
| 催促 vs 反馈 | 催促=推动进度，反馈=表达意见 | "朋友迟到"→正确归反馈 ✅ |
| 反馈 vs 设边界 | 反馈=建设性意见，设边界=捍卫权益 | "妈妈催婚"→正确归设边界 ✅ |

**对策**:
- [x] 规则关键词库中已有足够区分度 (不同意图有独立关键词集)
- [ ] 对置信度 < 0.7 的边界案例增加追问确认

### 弱点4: 关系类型粒度不够精确 ⚠️ (严重度: 低)

**现象**: 规则词典有 32 种关系子类型 (如"同事(关系好)""同事(一般)"等)，但当前场景描述中的关键词命中过于宽泛。

**根因**:
- "同事"关键词同时命中"同事(一般)"和"同事(关系好)"两条 → 当前逻辑只取分数第一
- 场景描述 "同事总在下班后发消息" 无法区分是关系好还是一般

**对策**:
- [ ] 增加语义分析层: 不仅匹配关键词，还要分析描述中的情感倾向
- [ ] 多候选展示: 当多个关系类型分数接近时展示所有候选

### 弱点5: 极端/边缘场景未充分测试 ⚠️ (严重度: 中)

**未覆盖的场景类型** (Day 13 计划):
- 空字符串 / 超长文本 >1000字
- 纯英文 / 纯表情 / 多意图混合
- 双重关系冲突 (同事+好友)
- 文化敏感场景 (拒长辈敬酒)
- 高风险场景 (道歉涉及信任背叛)

**对策**:
- 📅 Day 13 社交困境专项测试 (已排期)
- 📅 Day 13 Bug Bash (三人同时自由测试)

### 弱点6: 缺乏效果量化自动评估 ⚠️ (严重度: 高)

**现象**: 当前只能通过人工阅读判断生成质量，无法自动量化。

**缺失的量化指标**:
- 生成回复的礼貌度评分
- 策略多样性评分 (三版本是否真的提供了不同策略)
- 用户满意度模拟

**对策**:
- [ ] W3: 引入 LLM-as-Judge 自动评分
- [ ] W3: 建立黄金标准测试集 (人工标注的理想回复)
