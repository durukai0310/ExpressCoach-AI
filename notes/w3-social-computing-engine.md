## 一、推理链完整流程

ExpressCoach 的社交计算引擎采用**六阶段串行推理链**，从用户输入的原始场景描述到最终生成社交表达建议，每个阶段都有明确的输入、处理和输出。

```
┌─────────────────────────────────────────────────────────────────────┐
│                    社交计算推理链 (Inference Chain)                   │
├──────────┬──────────┬──────────┬──────────┬──────────┬──────────────┤
│ 场景输入 │ 意图分类 │ 关系计算 │ 策略选择 │ 风格分配 │ 回复生成     │
│ Scene    │ Intent   │ Relation │ Strategy │ Style    │ Generation   │
│ Input    │ Classify │ Compute  │ Select   │ Allocate │              │
├──────────┼──────────┼──────────┼──────────┼──────────┼──────────────┤
│ 用户原话 │ 规则匹配 │ 四维公式 │ 策略矩阵 │ EQ/Firm/ │ 三版本并行   │
│ +描述    │ + LLM    │ +词典    │ +场景    │ Mild     │ + LLM生成    │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────────┘
```

### 阶段详解

#### 阶段 1: 场景输入 (Scene Input)
- **输入**: 用户原始文本，如 "我想拒绝朋友借钱但不想伤感情"
- **处理**: 提取场景中的**角色**（说话者、对方）、**动作意图**、**关系线索**
- **输出**: 结构化场景对象 `{ user, target, action, constraint, tone }`

#### 阶段 2: 意图分类 (Intent Classification)
- **输入**: 场景对象
- **处理**: 
  - 第一层：`data/intent-rules.json` 关键词规则匹配（5类 × ~20关键词）
  - 第二层：LLM 二次确认（规则置信度 < 0.7 时触发）
- **输出**: 意图类别 `{ intent: "拒绝"|"催促"|"反馈"|"设边界"|"求助", confidence: 0.0-1.0 }`

#### 阶段 3: 关系计算 (Relationship Computing) ⭐核心
- **输入**: 场景对象 + 意图
- **处理**: 
  - 关键词匹配 `data/relation-dict.json`（32种关系类型）
  - 四维加权公式计算综合敏感度（详见第二章）
  - 输出关系画像
- **输出**: `{ relationType, intimacy, power, interest, sensitivity, cultureRegion, sensitivityModifier }`

#### 阶段 4: 策略选择 (Strategy Selection)
- **输入**: 关系画像 + 意图类别
- **处理**: 策略矩阵映射（4维度 × 5意图 → 20种策略组合，详见第三章）
- **输出**: `{ primaryStrategy, fallbackStrategy, tone, cautionFlag }`

#### 阶段 5: 风格分配 (Style Allocation)
- **输入**: 策略对象
- **处理**: 根据敏感度将生成任务分配到三种风格引擎
  - 高敏感 → `generator-eq.md`（高情商柔和风）
  - 中敏感 → `generator-mild.md`（温和不失分寸）
  - 低敏感 → `generator-firm.md`（坚定直接）
- **输出**: `{ styleAllocation: { primary: "eq"|"mild"|"firm", temperature: 0.3-0.7 } }`

#### 阶段 6: 回复生成 (Reply Generation)
- **输入**: 风格配置 + 场景 + 策略
- **处理**: LLM 并行生成三个版本，每个版本使用独立的 System Prompt
- **输出**: `[version1, version2, version3]` — 分别发往社交反应预测模块

## 二、关系计算四维公式

### 2.1 公式定义

```
综合敏感度 (Sensitivity) = 
    亲密度权重 × 0.35 
  + 权力权重 × 0.30 
  + 利益权重 × 0.25 
  + 语境权重 × 0.10 
  + sensitivityModifier（微调因子）
```

### 2.2 各维度权重说明

| 维度 | 权重 | 评分范围 | 说明 |
|------|------|----------|------|
| **亲密度 (Intimacy)** | 0.35 | 1-4 | 亲密=1, 较近=2, 一般=3, 疏远=4 |
| **权力关系 (Power)** | 0.30 | 1-4 | 己方上位=1, 平等=2, 对方上位=3, 不明=2.5 |
| **利益关联 (Interest)** | 0.25 | 1-3 | 纯情感=1, 弱利益=2, 强利益=3 |
| **语境附加 (Context)** | 0.10 | 0-2 | 正面语境=0, 中性=0.5, 紧张语境=1, 冲突语境=2 |

### 2.3 权重设计依据

**亲密度 0.35（最高权重）**：在中国社交文化中，关系的亲疏直接决定了表达方式。对家人可以直接说 "不行"，对陌生人则需要高度客气。亲密度是社交表达的第一决定因素。

**权力关系 0.30（次高权重）**：上下级关系在中文语境中极为敏感。向老板提意见和向同事提意见，即使内容完全相同，表达方式差异巨大。权力不对等直接触发 "面子" 维护机制。

**利益关联 0.25（重要补正）**：即使关系亲密，一旦涉及强利益（如借钱、分财产），社交复杂度急剧上升。这也是为什么很多 "挚友借钱" 场景比 "拒绝陌生人" 更难处理。

**语境附加 0.10（情境微调）**：同一关系在不同语境下敏感度不同。如日常催同事交报告（中性）vs 在对方刚被批评后催（紧张），后者需要更多铺垫。

### 2.4 敏感度评分区间

| 综合分数 | 敏感度等级 | 策略建议 |
|----------|-----------|----------|
| 1.0 - 1.8 | **低敏感** | 可以直接表达，少铺垫，多用 "我" 句式 |
| 1.9 - 2.8 | **中敏感** | 适度礼貌，说明理由，给对方台阶 |
| 2.9 - 4.0 | **高敏感** | 充分铺垫，多共情，用 "我们" 句式，准备备选方案 |

### 2.5 sensitivityModifier 微调因子

| 微调类型 | 修正值 | 触发条件 |
|----------|--------|----------|
| 文化敏感区 +0.3 | 涉及中国传统文化禁忌（死亡、离婚、不孝） |
| 多意图混合 +0.2 | 用户同时表达两个及以上意图 |
| 有历史冲突 +0.25 | 场景提及 "上次"、"又"、"一直" 等重复性 |
| 角色双重身份 +0.2 | 对方同时具有两种关系（如：同事+好友） |
| 公共场合 +0.15 | 对话发生在公开场合（如会议、聚餐） |
| 私下场合 -0.1 | 一对一私下交流 |
| 关系缓冲期 -0.15 | 刚认识/关系修复期，双方都在试探 |

## 三、策略矩阵：4 维度 × 5 意图 → 20 种策略

### 3.1 策略矩阵总览

| 关系维度 ↓ / 意图 → | 拒绝 Refuse | 催促 Urge | 反馈 Feedback | 设边界 Boundary | 求助 Request |
|---------------------|------------|-----------|-------------|----------------|--------------|
| **高敏感** (上级/客户/长辈) | [S1] 感谢+理由+方案 | [S2] 汇报进度+表达理解+请求指示 | [S3] 先肯定+以提问方式+给台阶 | [S4] 委婉铺垫+规则化+不针对人 | [S5] 表达尊重+说明困难+请求意见 |
| **中敏感-利益** (同事/伙伴/一般关系) | [S6] 共情+原则+替代方案 | [S7] 事实+截止日期+主动帮助 | [S8] 三明治法(好-改进-好) | [S9] 规则前置+角色分离+共赢 | [S10] 说明理由+互惠承诺+给对方出口 |
| **中敏感-情感** (同学/室友/普通朋友) | [S11] 诚实+关心+建议 | [S12] 友好提醒+表示理解+共同目标 | [S13] 以"我"开头+描述感受+征求意见 | [S14] 温柔坚定+说明影响+邀请合作 | [S15] 先关心近况+自然过渡+降低压力 |
| **低敏感** (家人/挚友/平级熟人) | [S16] 直说原因+幽默化解+即刻反馈 | [S17] 直接提醒+表达信任+短期期限 | [S18] 直接反馈+用举例+以关系担保 | [S19] 直接声明+解释原因+确认理解 | [S20] 直接开口+强调感情+表达感谢 |

### 3.2 20种策略详细方案

#### 🔴 高敏感场景 (上级/客户/长辈/导师)

**S1: 拒绝 — "感谢+理由+方案"**
- 句式框架: "非常感谢您的...确实因为...不过我可以..."
- 核心原则: 给对方台阶下 + 提供替代方案
- 禁忌: 不能说 "不行"、"没办法"（显得消极）
- 示例: "感谢领导信任我负责这个项目。确实因为手上已有三个紧急任务，如果再接可能会影响交付质量。要不我推荐小王？他对这块很熟。"

**S2: 催促 — "汇报进度+表达理解+请求指示"**
- 句式框架: "关于...目前进展是...理解您那边也忙...您看什么时候方便..."
- 核心原则: 把催促包装成 "汇报 + 征求意见"
- 禁忌: 不能说 "你还没"、"你怎么还不"
- 示例: "关于上周的需求文档，我们这边开发已经排期了。理解您那边也很多事，您看这周内能帮忙确认吗？有什么需要我协助的？"

**S3: 反馈 — "先肯定+以提问方式+给台阶"**
- 句式框架: "您的...确实有道理...我有一个不太成熟的想法...当然可能是我没理解到位"
- 核心原则: 把意见包装成 "请教" 或 "确认"
- 禁忌: 不能说 "你错了"、"这不对"

**S4: 设边界 — "委婉铺垫+规则化+不针对人"**
- 句式框架: "最近注意到...我理解这不是故意的...我们可以建立一个..."
- 核心原则: 把个人边界包装成 "共同规则"
- 禁忌: 不能说 "你总是"、"你每次都"

**S5: 求助 — "表达尊重+说明困难+请求意见"**
- 句式框架: "一直很佩服您在...方面的经验...我最近遇到...想请教您..."
- 核心原则: 先表达对对方专业能力的认可
- 禁忌: 不能显得理所当然

#### 🟡 中敏感-利益 (同事/合作伙伴/一般关系+利益关联)

**S6: 拒绝 — "共情+原则+替代方案"**
- 句式框架: "我特别理解...但我个人的原则是...不过我可以..."
- 核心原则: 拒绝的是事，不是人

**S7: 催促 — "事实+截止日期+主动帮助"**
- 句式框架: "目前...的数据是这样的...我们周五前需要...你看我这边能帮你什么？"

**S8: 反馈 — "三明治法"**
- 句式框架: "[做得好] → [可以改进] → [我相信]"

**S9: 设边界 — "规则前置+角色分离+共赢"**
- 句式框架: "为了我们更好地配合...以后...这样对我们都好"

**S10: 求助 — "说明理由+互惠承诺+给对方出口"**
- 句式框架: "因为...我想请你...这次帮我...下次你有需要我一定..."

#### 🟢 中敏感-情感 (同学/室友/普通朋友)

**S11: 拒绝 — "诚实+关心+建议"**
- 句式框架: "说实话...不是不想帮...我建议你..."
- 核心原则: 诚实但不伤人

**S12: 催促 — "友好提醒+表示理解+共同目标"**
- 句式框架: "提醒一下...我知道你可能忙...我们一起..."

**S13: 反馈 — "我句式+描述感受+征求意见"**
- 句式框架: "我注意到...我有点...你怎么看？"

**S14: 设边界 — "温柔坚定+说明影响+邀请合作"**
- 句式框架: "有件事我一直想跟你说...对我影响是...我们能不能..."

**S15: 求助 — "先关心近况+自然过渡+降低压力"**
- 句式框架: "最近怎么样？...对了，有件事想请教..."

#### 🔵 低敏感 (家人/挚友/平级熟人)

**S16: 拒绝 — "直说+幽默+快速"**
- 句式框架: "说实话这个不行...（加个玩笑）...下次一定！"

**S17: 催促 — "直接提醒+信任+短期期限"**
- 句式框架: "别忘了...我相信你...今天能搞定吗？"

**S18: 反馈 — "直接+举例+关系担保"**
- 句式框架: "我跟你说真的...比如...咱们这关系我才直说"

**S19: 设边界 — "直接声明+解释+确认"**
- 句式框架: "以后...因为...你理解的吧？"

**S20: 求助 — "直接开口+强调感情+表达感谢"**
- 句式框架: "帮我个忙...咱俩谁跟谁...谢了！"

### 3.3 策略选择决策树

```
输入: 关系画像 {intimacy, power, interest, context} + 意图 {intent}
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
   综合敏感度    意图类型    语境修正
   ≥2.9 高敏    拒绝/催促    +/- tier
   1.9-2.8 中   反馈/边界    调整一级
   <1.9 低敏    求助         或不变
        │           │           │
        └───────────┼───────────┘
                    ▼
              ┌──────────┐
              │ 策略编号  │
              │ S1 - S20 │
              └──────────┘
```

## 四、三个完整案例 — 走完整推理链

### 案例 1: "我想拒绝朋友借钱但不想伤感情"

#### 推理链过程

**阶段 1 — 场景输入解析**:
```json
{
  "user": "说话者",
  "target": "朋友",
  "action": "拒绝",
  "constraint": "不伤感情",
  "tone": "犹豫、愧疚"
}
```

**阶段 2 — 意图分类**:
- 规则匹配: 关键词 "拒绝" + "借钱" + "不想" → intent = "拒绝"
- LLM 确认: 一致（高置信度 0.92）
- 输出: `{ intent: "拒绝", confidence: 0.92, subIntent: "金钱相关拒绝" }`

**阶段 3 — 关系计算**:
- 关系词典匹配: "朋友" → 先匹配 "好朋友"（默认）
- 四维评分:
  - 亲密度: "较近" = 2 → 2 × 0.35 = 0.70
  - 权力关系: "平等" = 2 → 2 × 0.30 = 0.60
  - 利益关联: "纯情感" → 但借钱触发 "强利益" = 3 → 3 × 0.25 = 0.75
  - 语境附加: "紧张语境"（涉及金钱）= 1 → 1 × 0.10 = 0.10
  - sensitivityModifier: 文化敏感区（金钱往来）+0.3
- **综合敏感度**: 0.70 + 0.60 + 0.75 + 0.10 + 0.30 = **2.45 → 中敏感**
- 输出: `{ relationType: "好朋友", sensitivity: "中敏感", score: 2.45 }`

> ⚠️ 关键洞察: 虽然是 "好朋友"（亲密度较低分），但因为涉及金钱利益，综合敏感度从 "低敏感" 跃升到 "中敏感"。这正是四维公式的价值——不能只看关系类型。

**阶段 4 — 策略选择**:
- 定位: 中敏感-情感 × 拒绝 → **S11: "诚实+关心+建议"**
- 策略内容: 诚实但不伤人的拒绝，表达关心，提供建议
- 备选策略: S6（如果对方是同事+好友双重身份）

**阶段 5 — 风格分配**:
- 敏感度 2.45 → 中敏感
- 分配: `{ primary: "mild", temperature: 0.4, secondary: "eq" }`

**阶段 6 — 三版本生成**:
- Version 1 (mild): "说实话兄弟，我最近手头也紧，刚交完房租。不是不想帮，是真的有心无力。要不你看看能不能分期或者找其他渠道？"
- Version 2 (eq): "谢谢你信任我跟我开口。我现在的经济情况确实不允许，但我不想因为这个影响我们的关系。如果你需要，我可以帮你一起想办法。"
- Version 3 (firm): "抱歉，我现在确实借不了。不是针对你，是我个人的原则——不跟朋友有金钱往来。希望你能理解。"

#### 完整推理链 JSON 输出

```json
{
  "caseId": "reject-friend-borrow",
  "inferenceChain": {
    "sceneInput": { "user": "说话者", "target": "朋友", "action": "拒绝", "constraint": "不伤感情" },
    "intentClassify": { "intent": "拒绝", "confidence": 0.92, "subIntent": "金钱相关拒绝" },
    "relationCompute": {
      "relationType": "好朋友",
      "intimacy": "较近", "intimacyScore": 0.70,
      "power": "平等", "powerScore": 0.60,
      "interest": "强利益", "interestScore": 0.75,
      "context": "紧张语境", "contextScore": 0.10,
      "sensitivityModifier": 0.30,
      "totalScore": 2.45, "sensitivity": "中敏感"
    },
    "strategySelect": { "primary": "S11", "strategy": "诚实+关心+建议", "fallback": "S6" },
    "styleAllocate": { "primary": "mild", "temperature": 0.4 },
    "replyGenerate": ["version1_mild", "version2_eq", "version3_firm"]
  }
}
```

### 案例 2: "催同事交报告又不想把关系搞僵"

#### 推理链过程

**阶段 1 — 场景输入解析**:
```json
{
  "user": "说话者",
  "target": "同事(关系一般)",
  "action": "催促",
  "constraint": "不搞僵关系",
  "urgency": "中等"
}
```

**阶段 2 — 意图分类**:
- 规则匹配: 关键词 "催" + "交报告" → intent = "催促"
- LLM 确认: 一致（置信度 0.88）
- 输出: `{ intent: "催促", confidence: 0.88, subIntent: "工作交付催促" }`

**阶段 3 — 关系计算**:
- 关系词典匹配: "同事" → "同事(一般)"
- 四维评分:
  - 亲密度: "一般" = 3 → 3 × 0.35 = 1.05
  - 权力关系: "平等" = 2 → 2 × 0.30 = 0.60
  - 利益关联: "弱利益" = 2 → 2 × 0.25 = 0.50
  - 语境附加: "工作场合-中性" = 0.5 → 0.5 × 0.10 = 0.05
  - sensitivityModifier: 无特殊触发 = 0
- **综合敏感度**: 1.05 + 0.60 + 0.50 + 0.05 + 0 = **2.20 → 中敏感**

**阶段 4 — 策略选择**:
- 定位: 中敏感-利益 × 催促 → **S7: "事实+截止日期+主动帮助"**

**阶段 5 — 风格分配**:
- 敏感度 2.20 → 中敏感
- 分配: `{ primary: "mild", temperature: 0.5 }`

**阶段 6 — 三版本生成**:
- Version 1 (mild/fact): "Hi，关于上周的需求报告，咱们周五前需要提交给领导。目前我这边看到进度还是待完成状态——有需要我帮忙整理的地方吗？"
- Version 2 (eq/soft): "不好意思打扰一下~我知道你最近也挺忙的。就是那个报告周五 deadline，领导已经在问了。有什么我能帮你分担的吗？"

## 五、三案例对比分析

| 对比维度 | 案例1: 拒绝借钱 | 案例2: 催报告 | 案例3: 提意见 |
|----------|---------------|-------------|-------------|
| 意图 | 拒绝 | 催促 | 反馈 |
| 关系类型 | 好朋友 | 同事(一般) | 上级 |
| 亲密度 | 较近 (2) | 一般 (3) | 一般 (3) |
| 权力 | 平等 (2) | 平等 (2) | 对方上位 (3) |
| 利益 | 强利益 (3) | 弱利益 (2) | 强利益 (3) |
| 语境 | 紧张 (1) | 中性 (0.5) | 紧张 (1) |
| 微调因子 | +0.30 | 0 | +0.45 |
| **综合敏感度** | **2.45 中敏感** | **2.20 中敏感** | **3.25 高敏感** |
| 策略编号 | S11 | S7 | S3 |
| 风格引擎 | mild | mild | eq |
| 核心策略 | 诚实+关心 | 事实+帮助 | 先肯定+提问 |

### 关键发现

1. **同一敏感度区间内的精细化差异**: 案例1和案例2都是 "中敏感"，但案例1 (2.45) 接近高敏感阈值，案例2 (2.20) 偏中低。实际应用中案例1需要比案例2更多的情感铺垫。

2. **利益维度的敏感性**: 案例1虽然是 "好朋友"（亲密度高于案例3的 "老板"），但因为涉及金钱，加上文化敏感微调，综合敏感度远高于期望值。这验证了四维公式中 "利益" 维度的权重合理性。

3. **微调因子的关键作用**: 案例3的 sensitivityModifier (+0.45) 占了总分 3.25 的约 14%，如果没有微调因子，敏感度会从 3.25 降到 2.80，可能错误地归类到 "中敏感"——这对 "向老板提意见" 来说是不够的。

## 六、技术总结

### 推理链核心价值

1. **可解释性**: 每一步都有明确的输入输出，答辩时可逐阶段解释 "为什么给出这个建议"
2. **可调试性**: 如果输出不满意，可以追溯到具体阶段（是关系判断错了？还是策略选错了？）
3. **可量化**: 四维公式将 "社交敏感度" 从天概念转化为可计算、可对比的数值
4. **覆盖面**: 4关系维度 × 5意图 = 20种策略组合 + sensitivityModifier 微调 → 覆盖绝大多数中文社交场景

| 文化适配 | 通用中文 | 中国文化特化（面子/孝道/师道） |
