# ExpressCoach 伦理声明

**版本**: 2.0.0 | **日期**: 2026-07-02 | **阶段**: W5 最终版

> **声明性质**: 本文档是 ExpressCoach 项目在伦理与社会责任维度的正式立场声明。它不仅是答辩的形式要求，更是团队在设计、开发和评测全过程中实际遵循的伦理准则。我们相信，一个介入人类社交决策的 AI 系统，其伦理考量不应该是"事后补充"，而应该是"设计前置"。

---

## 1. 数据隐私与用户数据保护

ExpressCoach 从架构设计的第一天起就贯彻了**数据最小化**和**本地优先**原则。

**存储策略**: 所有用户数据——包括对话历史、场景输入、生成的回复文本、关系画像——均存储于用户本地的 SQLite 数据库文件中，不上传至任何云端服务器。系统不依赖任何远程数据库或第三方数据中台。用户对自身数据拥有完全的所有权和控制权。

**API 调用中的隐私保护**: 当系统调用 LLM API（如 DeepSeek API）进行语义推理和文本生成时，传输的数据仅限于当前场景的结构化信息和必要的上下文提示。我们不会在 API 请求中包含用户的个人身份信息（PII），也不会将用户的历史对话数据用于模型训练或任何形式的遥测。`.env` 文件已加入 `.gitignore`，确保 API Key 等敏感凭证不会意外提交至版本控制系统。

**用户数据权利**: 用户可以随时查看本地数据库中存储的所有数据（通过 CLI 的 `--history` 模式），可以随时删除全部或部分个人数据（通过 `--clear` 命令），且系统不设置任何形式的数据留存后门或静默上传机制。

**安全边界**: 我们建议用户不要在与 ExpressCoach 的交互中输入个人身份证号、银行卡号、家庭住址等高度敏感的个人信息。尽管这些信息同样存储于本地，但本地文件的安全性取决于用户自身设备的安全状态。我们计划在未来版本中增加敏感信息自动脱敏检测功能。

## 2. AI 建议的局限性

ExpressCoach 提供的所有表达策略和回复建议**均基于算法推理与统计模式识别**，绝非"社交真理"。

**核心定位**: ExpressCoach 是一个**社交表达辅助工具**，而非**社交决策替代系统**。它帮助用户理解社交场景的结构（关系维度、策略空间、风险点），但最终的沟通决策——包括是否使用、如何使用、何时使用生成的回复——完全由用户自主决定。

**不可替代的领域**: 以下场景中，ExpressCoach 的建议**不能也不应**替代专业意见：
- **法律场景**: 涉及合同、诉讼、法律责任声明的沟通 → 请咨询持证律师。
- **HR/劳动关系场景**: 涉及解雇、降职、劳动仲裁的沟通 → 请咨询 HR 专业人员或劳动法律师。
- **医疗/心理健康场景**: 涉及严重心理创伤、危机干预、自杀风险的沟通 → 请立即寻求专业心理医生或危机干预热线帮助。
- **家庭暴力/虐待场景**: 请拨打当地家庭暴力救助热线，ExpressCoach 的设计边界不覆盖此类高风险场景。

**评估结果的局限性**: 当前评测基于 10-20 个精心设计的标准场景和 300+ 条训练数据，尚未在万人级真实用户场景中进行大规模随机对照试验。87.5% 的极端场景通过率（55% 能处理 + 35% 勉强可处理）意味着仍有 10% 的场景系统诚实标注为"无法处理"——这些标注本身就是系统伦理边界的一部分。

## 3. 我们不鼓励的行为

ExpressCoach 的设计目标是为**真诚的社交沟通**提供帮助，而非为**不良意图**提供技术便利。

**明确禁止的使用场景**:
- **欺骗与谎言**: 系统不应被用于编造虚假信息以欺骗他人。例如："帮我编个理由骗老板说我生病了"——当规则引擎检测到"骗"、"装病"等关键词时，系统应拒绝生成或输出警告。
- **情感操纵与 PUA**: 任何形式的恶意社交操控——包括但不限于精神控制（PUA）、煤气灯效应（Gaslighting）、情感勒索——均不在系统的设计意图之内。策略库中的"面子协商"和"互惠原则"是**建设性社交技巧**，不是操纵手段。
- **骚扰与威胁**: 系统不应帮助用户生成骚扰信息、威胁信息或任何形式的暴力内容。
- **违法活动**: 任何违反中华人民共和国法律的行为——包括但不限于诈骗、敲诈、非法集资相关的表达策略——均被严格禁止。

**技术保障措施**: 我们在策略矩阵中为每类策略预定义了**禁忌清单**。例如，S11 策略（诚实+关心+建议）的禁忌清单明确标注"不可使用虚假同情"、"不可利用对方情感弱点"。在 W4 增强中，我们为敏感场景增加了 `cautionFlag` 字段，当检测到高风险意图时系统会在输出中附加"⚠️ 本回复仅为参考，请基于真实情况判断"的醒目提醒。

**边界模糊场景的处理**: 我们承认，某些场景的判断是困难的——"如何委婉地拒绝"和"如何巧妙地逃避"之间的边界并不总是清晰。对此，我们的原则是**输出警告 > 静默生成**：当规则引擎对意图的置信度低于阈值时，系统主动向用户说明风险，而非直接输出可能存在伦理问题的回复。

## 4. 偏见意识与文化局限性

ExpressCoach 的关系词典和文化微调因子**基于中国大陆当代社交规范**，这一选择既是系统的核心优势，也是其最根本的偏见来源。

**承认的偏见维度**:
- **地域偏见**: 32 种关系类型和 7 类文化微调因子主要反映中国大陆城市中产阶级的社交规范。对港台地区、海外华人社群、农村地区、少数民族文化圈的社交规范覆盖严重不足。
- **代际偏见**: 关系词典中的"权力距离感"可能更偏向 80/90 后的社交经验。00 后和 10 后的职场社交规范（更扁平化、更直接）未被充分建模。
- **性别偏见**: 当前模型未显式考虑性别对社交表达的影响。在"向女/男性老板提意见"这样的场景中，性别可能影响社会期望和表达策略，但这一维度尚未被量化建模。
- **行业偏见**: "职场"关系类型基于通用白领办公场景建模，对蓝领工人、自由职业者、创意行业从业者的社交规范适配不足。
- **语言偏见**: 当前仅支持简体中文，对繁体中文、方言掺杂表达（如粤语/上海话词汇嵌入普通话）的处理能力有限。

**缓解措施（当前）**:
- 在系统输出中明确标注 `cultureRegion: "mainland"`，提醒用户当前策略基于中国大陆社交规范。
- 在竞品对比和局限声明中坦诚标注文化覆盖盲区。
- 提供 CLI `--culture` 参数接口（W4），为未来多文化适配预留架构空间。

**缓解措施（计划）**:
- W5+ 扩展至港台和东南亚华语文化圈的关系建模。
- 引入可配置的"权力距离"偏好参数，允许用户调整模型的层级敏感度。
- 在文档中增加"文化适用性声明"，明确告知用户本工具的适用范围边界。

## 5. 社交焦虑与心理健康

ExpressCoach 的设计初衷是**赋能**而非**依赖**——我们帮助用户在社交场景中更自信地表达自己，但绝无意让用户形成对 AI 的工具性依赖。

**我们是什么**: ExpressCoach 提供的是**表达技巧**和**社交结构分析**。它像一个友好的教练，帮你理清"在这个关系中，我该怎么说"的思路。它帮助用户看到社交场景中隐藏的结构——权力关系、利益关联、文化敏感区——从而做出更明智的沟通决策。

**我们不是什么**: ExpressCoach **不是**心理咨询替代品，**不是**认知行为疗法（CBT），**不是**社交焦虑障碍（SAD）的临床干预工具。如果用户正在经历严重的社交焦虑——包括但不限于：面对所有社交场景都感到极度恐惧、回避社交导致正常生活严重受限、伴随心悸/出汗/颤抖等躯体症状——我们强烈建议寻求专业心理咨询师或精神科医生的帮助。

**健康的工具观**: 最好的社交教练最终会让学生不再需要教练。ExpressCoach 的六阶段推理链设计本身具有**教育价值**——用户可以通过观察系统的推理过程（为什么在这个关系中要这样说？关系维度是如何计算的？）来逐步内化社交判断能力，最终形成自己的社交直觉。我们不希望用户成为"离开 AI 就不会说话"的人。

**紧急情况**: 如果用户表达了自伤或自杀意图，系统的回应应该是即时提供当地心理危机干预热线号码，而非生成任何形式的"社交建议"。

## 6. 透明度承诺

透明度是 ExpressCoach 伦理框架的基石。我们相信用户有权知道自己正在与什么系统交互，以及系统输出的来源和依据。

**AI 身份透明**:
- 用户始终清楚地知道自己正在与 AI 系统交互。ExpressCoach 不会在任何环节冒充真实人类。
- 所有 LLM 生成的回复文本均明确标注为"AI 生成"。
- 在多 Agent 沙盒模式下，Simulator Agent 模拟的对方回复标注为"模拟对话（非真实人类回复）"。

**推理过程透明**:
- 六阶段推理链的输出在 `--verbose` 模式下**完全可见**：用户可以看到意图分类的结果和置信度、四维关系计算的过程和最终得分、策略选择的具体映射、风格分配的依据、以及最终生成的完整上下文。
- 这种可追溯性不仅是工程调试的需要，更是**对用户的尊重**——用户不应该面对一个"不知道为什么给出这个建议"的黑盒系统。

**模型与数据透明**:
- 本文档第 2 节明确说明了当前评测的规模和局限性。
- 竞品对比报告中的评测方法、评分维度和评测者间信度均公开可查。
- 我们不会夸大系统的能力边界——在 20 项极端困境中 10% 无法处理的场景，我们在所有材料中都诚实标注。

**透明度不意味着放弃知识产权**: 虽然我们承诺推理过程的透明，但四维计算模型的具体权重系数、策略矩阵的设计细节、以及训练数据的标注方法等核心知识产权，在公开发布时可能需要在透明度和商业保护之间取得平衡。这一平衡的最终判断属于项目团队和导师。

## 7. 责任归属

AI 辅助社交决策系统引入了一个复杂的责任归属问题：当用户采用了系统建议的表达策略却导致了不良后果时，责任应该由谁承担？

**我们的立场**:

1. **最终决策权始终在用户手中**: ExpressCoach 提供的是"建议"而非"指令"。用户是最终的决策者，也应当是最终的责任承担者。正如一本社交指南书不会为读者的社交失败负责，ExpressCoach 也不应为用户的沟通决策负责。

2. **系统的"不可免责"边界**: 然而，以下情况中系统的设计者应承担部分责任：
   - 如果系统输出了明显违背伦理原则的建议（如鼓励欺骗、操纵他人），而系统未触发任何警告机制 → **这是设计缺陷**。
   - 如果系统在已知高风险场景中未提供足够的风险提示 → **这是透明度不足**。
   - 如果系统的关系计算出现根本性错误（如将上级误判为平级）导致策略选择严重失当 → **这是系统可靠性问题**。

3. **我们对用户的承诺**:
   - 我们将**持续标注系统的能力边界**——在每类可能产生负面后果的场景中，明确告知系统能做和不能做的事。
   - 我们将**持续改进风险检测机制**——在 W4 的 `cautionFlag` 基础上，W5+ 计划增加更细粒度的场景风险评估。
   - 我们接受**学术界和用户的公开审视**——本伦理声明、技术白皮书、竞品对比报告均以透明方式发布，欢迎批评和指正。

4. **法律责任的现实**: 在当前中国的法律框架下，AI 生成内容的著作权和侵权责任仍在发展中。ExpressCoach 作为一个学术研究项目（非商业化产品），其法律责任边界与商业化的 AI 产品有所不同。但我们选择以**高于法律最低要求的标准**来约束自己——因为赢得用户的信任比规避法律风险更重要。

---

## 结语：伦理是设计，不是补丁

在 ExpressCoach 的开发过程中，伦理考量不是事后追加的"免责声明"，而是融入架构设计的有机组成部分。从数据本地存储的隐私设计，到策略矩阵中每个策略的禁忌清单，到 `cautionFlag` 的风险检测机制，到六阶段推理链的透明输出——每一个技术决策背后都包含了"我们应该这样做吗？"而不仅仅是"我们能这样做吗？"的伦理反思。

我们深知，一个介入人类社交生活的 AI 系统，其影响力远超其代码量。一句不当的社交建议可能伤害一段真实的关系，而一个清晰的伦理框架则可能帮助用户做出更明智、更真诚的社交选择。这正是 ExpressCoach 存在的意义，也是这份伦理声明的全部价值。
