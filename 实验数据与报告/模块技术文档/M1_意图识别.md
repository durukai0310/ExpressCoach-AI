# M1 意图识别模块

## 功能概述

意图识别模块（M1）是 ExpressCoach 的入口模块，负责从用户输入的自然语言场景描述中识别出核心社交意图。该模块是后续关系分析和策略生成的基础，准确的意图识别直接影响整个系统的效果。

**核心功能**：
- 接收用户输入的场景描述
- 调用 DeepSeek API 进行意图分类
- 返回意图类型、紧急度和重要性三个核心指标
- 支持5种意图类型：拒绝请求、催促对方、提出反馈、设立边界、寻求帮助
- 支持多标签识别（一个场景可能包含多个意图）
- 规则兜底机制，当 LLM 识别失败时使用关键词匹配

**设计目标**：
- 准确率 ≥ 90%
- 响应时间 < 2秒
- 覆盖所有核心社交场景

## 核心算法

### 算法架构

模块采用 **LLM 驱动 + 规则兜底** 的混合策略：

```
┌─────────────────────────────────────────────────────────────┐
│                    意图识别流程                              │
├─────────────────────────────────────────────────────────────┤
│  输入: 场景描述                                             │
│       │                                                     │
│       ▼                                                     │
│  ┌──────────────┐                                          │
│  │  LLM识别     │  → 调用DeepSeek API                       │
│  └──────┬───────┘                                          │
│         │                                                  │
│    识别成功?                                                │
│         │                                                  │
│    ┌────┴────┐                                             │
│    │         │                                             │
│   Yes        No                                            │
│    │         │                                             │
│    ▼         ▼                                             │
│  返回结果   ┌──────────────┐                               │
│             │  规则兜底    │  → 关键词匹配                  │
│             └──────┬───────┘                               │
│                    │                                       │
│                    ▼                                       │
│              返回规则结果                                    │
└─────────────────────────────────────────────────────────────┘
```

### 提示词设计

基于预定义的 SOUL 文档构建提示词，包含：
- **意图定义**：5种意图的详细定义和判断标准
- **示例场景**：每种意图提供多个正例和反例
- **输出格式**：JSON 格式，包含意图、紧急度、重要性字段
- **边界情况**：歧义场景的处理规则
- **多标签提示**：允许返回多个意图标签

### 响应解析

采用三层解析策略确保鲁棒性：
1. **直接 JSON 解析**：尝试直接解析响应为 JSON
2. **代码块提取**：查找 ```json 代码块并解析
3. **大括号提取**：查找最外层大括号内容并解析

### 规则兜底机制

当 LLM 识别失败或置信度低于阈值时，启用规则兜底：
- 关键词词典：`data/intent-keywords.json`
- 匹配策略：基于场景中的关键词进行意图判断
- 优先级：拒绝请求 > 设立边界 > 提出反馈 > 催促对方 > 寻求帮助

### 重试机制

- 最大重试次数：2次
- 重试间隔：指数退避（1秒、2秒）
- 温度参数：0.1（确保输出一致性）

## 设计决策

### 为什么选择 LLM 而非规则？

**规则方法的局限性**：
- 需要维护庞大的关键词词典
- 难以处理复杂语义和歧义场景
- 扩展性差，新增意图需要大量规则
- 无法理解上下文关系

**LLM 方法的优势**：
- 理解上下文和语义
- 处理歧义场景能力强
- 易于扩展，只需更新 SOUL 文档
- 支持多标签识别

### 多标签识别的必要性

某些场景可能同时包含多个意图：
- "室友晚上打游戏声音太大，我想设边界但又不想伤感情" → 设立边界 + 拒绝请求
- "领导开会总是超时，我想提反馈同时提醒注意时间" → 提出反馈 + 催促对方

### 温度参数设置

选择 `temperature: 0.1` 的原因：
- 意图识别是确定性任务，需要稳定输出
- 低温度减少随机性，提高一致性
- 避免同一输入产生不同意图判断

### 核心函数

**recognizeIntent(scenario)**

```javascript
async function recognizeIntent(scenario) {
  const soulContent = loadFile(INTENT_SOUL, "Day8-SOUL(1).md");
  const { content } = await callDeepSeek(soulContent, scenario, {
    temperature: 0.1,
    maxTokens: 300,
    maxRetries: 2
  });
  
  const result = parseResponse(content);
  
  if (!result || !result.intent) {
    return fallbackToRules(scenario);
  }
  
  return { raw: content, parsed: result, method: "llm" };
}
```

**fallbackToRules(scenario)**

规则兜底函数，基于关键词匹配进行意图判断。

**callDeepSeek(systemPrompt, userInput, opts)**

封装 DeepSeek API 调用，包含重试机制和错误处理。

## 局限性

### 当前局限

1. **意图类型有限**：仅支持5种核心意图，对于复杂社交场景可能不够精细
2. **上下文理解有限**：单次调用无法理解对话历史，长对话场景处理能力不足
3. **规则兜底简单**：关键词匹配策略较为简单，无法处理复杂语义
4. **多标签冲突**：当多个意图同时存在时，优先级规则可能不够完善

### 改进方向

1. **扩展意图类型**：增加更多细分意图（如道歉、感谢、赞美等）
2. **上下文记忆**：引入对话历史存储，支持多轮对话理解
3. **增强规则引擎**：使用更复杂的规则匹配算法（如语义相似度）
4. **意图优先级学习**：基于用户反馈学习意图优先级权重
