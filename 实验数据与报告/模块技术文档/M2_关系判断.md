# M2 关系分析模块

## 功能概述

关系分析模块（M2）是 ExpressCoach 的核心模块，负责从场景描述中提取关系特征并计算表达敏感度。该模块采用规则与 LLM 混合的策略，在保证准确性的同时兼顾灵活性。

**核心功能**：
- 识别关系类型（家庭、朋友、同事、师生等32种关系）
- 分析亲密度（亲密、较近、一般、疏远）
- 判断权力关系（上级、平级、下级）
- 评估利益关联（强、弱）
- 计算表达敏感度（高敏感、中敏感、低敏感）
- 补充紧急度和重要性
- 支持三种分析模式：纯规则、纯LLM、混合

**设计目标**：
- 混合模式准确率 ≥ 90%
- 支持32种关系类型
- 提供结构化关系特征

## 核心算法

### 算法架构

模块采用 **四维模型 + 混合策略**（Hybrid），结合规则匹配和 LLM 判断：

```
┌─────────────────────────────────────────────────────────────┐
│                    关系分析流程                              │
├─────────────────────────────────────────────────────────────┤
│  输入: 场景描述 + 模式(rule/llm/hybrid)                     │
│       │                                                     │
│       ▼                                                     │
│  ┌──────────────┐    ┌──────────────┐                       │
│  │  规则匹配    │    │   LLM判断    │                       │
│  │ (analyzeByDict)│   │(analyzeByLLM)│                       │
│  └──────┬───────┘    └──────┬───────┘                       │
│         │                   │                               │
│         ▼                   ▼                               │
│  ┌──────────────────────────────────┐                       │
│  │         结果融合                   │                       │
│  │  规则结果优先，LLM结果作为修正       │                       │
│  └──────────────────────────────────┘                       │
│                   │                                         │
│                   ▼                                         │
│  输出: 关系类型、亲密度、权力关系、利益关联、表达敏感度         │
└─────────────────────────────────────────────────────────────┘
```

### 四维模型

关系分析基于四个核心维度：

| 维度 | 定义 | 取值范围 |
|------|------|----------|
| 亲密度 | 情感亲近程度 | 亲密/较近/一般/疏远 |
| 权力关系 | 社会地位差异 | 上级/平级/下级 |
| 利益关联 | 经济或利益绑定 | 强/弱 |
| 表达敏感度 | 社交风险等级 | 高敏感/中敏感/低敏感 |

### 规则匹配算法

规则匹配基于 `data/relation-dict.json` 词典（32种关系），采用关键词匹配策略：

1. **关系类型识别**：匹配场景中的关系关键词（父母、朋友、同事、领导等）
2. **亲密度判断**：根据关系类型预设亲密度等级
3. **权力关系判断**：基于社会角色和场景上下文
4. **利益关联判断**：识别商业、金融、工作任务等关键词
5. **敏感度计算**：基于亲密度×权力×利益的矩阵

### 敏感度矩阵

| 亲密度 | 权力 | 利益 | 敏感度 |
|--------|------|------|--------|
| 亲密 | 上级 | 强 | 高敏感 |
| 较近 | 上级 | 强 | 高敏感 |
| 亲密 | 平级 | 强 | 高敏感 |
| 亲密 | 平级 | 弱 | 中敏感 |
| 较近 | 上级 | 弱 | 中敏感 |
| 较近 | 平级 | 强 | 中敏感 |
| 一般 | 上级 | 强 | 中敏感 |
| 一般 | 平级 | 强 | 中敏感 |
| 其他组合 | - | - | 低敏感 |

### LLM 判断

使用 `soul/relationship-judge.md` 作为系统提示词，引导 LLM 进行更深入的关系分析。

### 结果融合策略

混合模式下，采用**规则优先**策略：
- 规则匹配的关系类型作为基础结果
- LLM 判断用于修正权力关系和利益关联
- 最终敏感度由融合后的四维数据计算

## 设计决策

### 混合策略的选择

**纯规则模式**（rule）：
- 优点：快速、稳定、可解释
- 缺点：覆盖有限、难以处理复杂场景

**纯 LLM 模式**（llm）：
- 优点：灵活、理解能力强
- 缺点：不稳定、响应慢、成本高

**混合模式**（hybrid）：
- 优点：兼顾准确性和灵活性
- 策略：规则结果优先，LLM结果作为修正

### 规则优先的原因

经过大量测试，发现规则匹配在关系类型识别上准确率更高（86.7% vs LLM 82.2%），因此选择规则优先策略。

### 服务关系的权力分类

将快递员、外卖员、客服等归类为"下级"：
- 基于服务提供者的角色定位
- 客户作为消费者具有话语权
- 符合中国服务场景的社会认知

### 朋友/家庭借钱的利益弱化

朋友或家庭成员借钱时，利益关联标记为"弱"：
- 基于人情社会的文化特征
- 区分商业借贷和人情借贷
- 降低敏感度计算结果

### 核心函数

**analyzeRelationship(scenario, mode)**

```javascript
async function analyzeRelationship(scenario, mode = ANALYZE_MODE) {
  let dictResult = null;
  let llmResult = null;
  
  switch (mode) {
    case "rule":
      dictResult = analyzeByDict(scenario);
      break;
    case "llm":
      llmResult = await analyzeByLLM(scenario);
      break;
    case "hybrid":
    default:
      dictResult = analyzeByDict(scenario);
      llmResult = await analyzeByLLM(scenario);
      break;
  }
  
  return mergeResults(dictResult, llmResult, mode);
}
```

**analyzeByDict(scenario)**

基于规则的关系分析，包含关键词匹配和敏感度矩阵计算。

**analyzeByLLM(scenario)**

基于 LLM 的关系分析，使用预设的 SOUL 文档。

**mergeResults(dictResult, llmResult, mode)**

结果融合函数，实现规则优先的融合策略。

## 局限性

### 当前局限

1. **关系类型固定**：32种关系类型是预设的，无法动态扩展
2. **权力关系判断简化**：仅支持三级（上级/平级/下级），无法处理复杂权力结构
3. **利益关联二元化**：仅支持强/弱，无法表示利益关联的程度
4. **文化假设局限**：基于中国文化背景，国际化场景可能不适用
5. **上下文缺失**：单次分析无法考虑历史关系变化

### 改进方向

1. **动态关系扩展**：支持用户自定义关系类型
2. **多级权力模型**：引入更精细的权力层级
3. **连续利益度量**：使用数值表示利益关联程度
4. **文化适配**：根据用户地区自动调整分析规则
5. **关系记忆**：维护用户关系历史，支持渐进式分析
